# Polka Poker v2.0.0.2 - Implementation Plan

## 1. Landing Page Refactor (Spectator Mode)
- **`src/ui/landing.js`**: Remove the Name and Avatar inputs from both the "Create Table" and "Join Table" forms.
- **`index.html` / `landing.css`**: Remove the DOM elements for Name and Avatar to simplify the initial entry screen.
- **Behavior**: Users clicking "Create" or "Join" will immediately connect to the session as a spectator. The `LocalStorage` read for profile data will be deferred to the seating phase.

## 2. In-Game Seat Claiming Modal (Onboarding)
- **`src/ui/table.js`**: 
  - Add state for `modalSeat` to track if the onboarding modal is open.
  - When "Sit Here" is clicked (`_makeSitHandler`), instead of immediately sending `MSG.SIT`, open the modal with the chosen seat index.
  - The modal will contain inputs for Name and Avatar (pre-filled from `LocalStorage` if available).
  - Upon submission, update `LocalStorage`, send `MSG.JOIN` with the profile, and then `MSG.SIT` with the seat index.
- **`src/styles/layout.css`**: Add CSS for a `.modal-overlay` (fixed position, 100vw/100vh, backdrop blur, flex centering) and `.modal-content` without using hard-coded pixel offsets.

## 3. Host Race Condition Handling
- **`src/engine/game.js` & `src/net/host.js`**: 
  - `game.sit()` already returns `{ok: false, error: 'That seat is taken'}` if a seat is occupied.
  - `host.js` forwards this error to the client via `MSG.ERROR`.
  - **`table.js`**: Will catch this error (via the existing toast mechanism) and close the seating modal if it fails, cleanly resolving race conditions.

## 4. Dynamic Chip Stacks
- **`src/ui/dom.js`**: Refactor the `chip(amount, className)` function. Instead of returning a simple pill, it will return a container `.chip-stack`.
- The `.chip-stack` will contain:
  - A visual stack of SVG chips (or styled `div`s). The number of visual chips will scale logarithmically or be capped at a `MAX_CHIPS` limit (e.g., max 10) to prevent layout disruption.
  - A numerical label overlapping or beside the stack.
- **`src/styles/chips.css`**: Style the `.chip-stack` using absolute/relative positioning so the visual chips overlap vertically, bounded within a fixed `height`/`width` to maintain the integrity of the CSS Grid table layout.

## Verification against Technical Guardrails
1. **Layout & Positioning**: The modal will use `position: fixed` with `display: flex; align-items: center; justify-content: center;` to center the content, strictly avoiding hard-coded pixel offsets.
2. **Modularity**: The UI changes remain strictly in `table.js` and `landing.js`, without altering the core `game.js` state machine.
3. **Data Integrity & Security**: All inputs in the modal will be rendered via `textContent` or `document.createElement` (via our `h` helper in `dom.js`), preventing XSS. LocalStorage will continue to store simple JSON `{playerName, avatarUrl}`.
4. **100vh Constraint**: The modal and chip stacks will not introduce scrolling. Chip stacks will have a maximum height defined in `variables.css` matching the grid cell constraints.
