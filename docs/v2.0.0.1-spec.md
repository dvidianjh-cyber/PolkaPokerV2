# Change Request: In-Table Player UI Integration
v2.0.0.0 -> v2.0.0.1

## 1. Objective
Eliminate vertical scrolling by moving the local player's hole cards and action dialogue buttons (Fold, Call, Raise) from below the main table graphic to inside the table layout, directly adjacent to the local player's avatar. 

## 2. UI/UX Updates
* **Viewport Constraint:** The main application container must be constrained to `100vh` with overflow hidden or managed to strictly prevent vertical browser scrolling.
* **Card & Button Relocation:** The player's active hole cards and action buttons must be rendered as an integrated grid item or flex container next to their avatar inside the primary table container.
* **Legibility:** Maintain the oversized, high-visibility SVG playing card design within the new spatial constraints.

## 3. Technical Guardrails & Constraints
* **Layout Method:** The repositioning must be achieved exclusively using CSS Grid or Flexbox[cite: 1]. 
* **Positioning:** Never use hard-coded pixel offsets for centering or placement[cite: 1].
* **Responsiveness:** The updated layout must remain functional and responsive down to a 320px screen width without breaking the container bounds[cite: 1].
* **Modularity:** Ensure that the DOM manipulation required for this new UI layout remains strictly separated from the underlying WebRTC and game business logic[cite: 1].

## 4. Definition of Done
* [ ] Player hole cards and action buttons render correctly inside the table area next to the avatar.
* [ ] No vertical scrollbar appears on standard desktop or mobile viewports.
* [ ] No placeholder comments (e.g., `// logic here`) remain in the updated UI code[cite: 1].
* [ ] `CHANGELOG.md` is updated with the version number, date, and details of this layout change[cite: 1].
