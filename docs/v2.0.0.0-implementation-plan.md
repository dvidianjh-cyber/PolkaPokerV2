# Plan of Action: WebRTC Texas Hold'em (v2.0.0.0)

Serverless client-side poker on GitHub Pages: Vite + ES6 modules + PeerJS. The Host is authoritative; peers only send actions and render state.

**Versioning:** four-part scheme. This is v2.0.0.0, and patches and features increment from there (v2.0.0.1, ...).

## Decisions (from review)
- **Seats:** maximum 8 players.
- **Blinds:** increase every N hands. The table creator configures N, the starting blinds and the buy-in.
- **Avatars:** V1 offers about 10 preset emoji. A later version will allow image upload, so the profile schema and message schema should allow an avatar to be either an emoji ID or image data.
- **Signaling:** the public PeerJS cloud broker is accepted.
- **Tests:** Vitest is allowed as a dev dependency.
- **Libraries:** reliable, stable public libraries are encouraged for poker rules and card SVGs, for example a maintained hand evaluator and `vector-playing-cards`. Each choice is vetted for maintenance, licence and size before adoption, and recorded in the changelog.

## Hand flow and dealer rotation
- The dealer button, small blind and big blind rotate clockwise to the next occupied seat each hand. Heads-up follows the standard rule (the dealer posts the small blind).
- Each hand ends in a **Showdown** state, shown with the winning hand and winner(s) and any split pots.
- The game then **pauses**. There is no timer, and nobody is auto-folded.
- Only the next dealer sees a **Deal next hand** button. The first hand is started the same way by the first dealer (the host, once at least 2 players are seated).
- Once a hand is dealt, the 60-second per-player timers run until that hand ends (timeout means check if there is no bet, otherwise fold).
- Between hands the Host applies blind increases, removes busted players (they become spectators or empty seats) and ends the game if one player is left.

State machine: `LOBBY -> WAITING_FOR_DEAL -> PREFLOP -> FLOP -> TURN -> RIVER -> SHOWDOWN -> WAITING_FOR_DEAL`

## Structure
```
index.html
vite.config.js        (base: './' for GitHub Pages)
CHANGELOG.md
src/
  main.js             bootstrap, screen routing
  storage/profile.js  LocalStorage {playerName, avatar}, validated
  net/                Module A
    peerHost.js       create table, join code, accept connections
    peerClient.js     join by code, error handling
    messages.js       schema + strict validation + sanitisation
    eventBus.js       named-handler pub/sub
  engine/             Module B (pure logic, no DOM)
    deck.js           crypto.getRandomValues Fisher-Yates
    evaluator.js      High Card..Royal Flush, kickers (library-backed if vetted)
    pots.js           main/side pots for all-ins
    blinds.js         blind schedule, increase every N hands
    dealer.js         dealer/SB/BB rotation
    game.js           state machine, bet validation, 60s timeout
  ui/                 Module C (DOM only)
    landing.js, table.js, controls.js, timer.js, cards.js, chips.js, showdown.js
  styles/             variables.css (theme, a11y), layout.css (Grid/Flex)
  assets/cards/       open-source SVG deck (four-colour option)
tests/                Vitest for evaluator, pots, blinds, rotation, game, validation
```

## Milestones
1. **Scaffold:** Vite, base config, CSS variables, changelog, headers (v2.0.0.0).
2. **Engine + tests:** deck, evaluator, side pots, blind schedule, dealer rotation, state machine with the pause-at-showdown flow, and the timeout rule.
3. **Networking:** PeerJS host/client, short join code, JSON schema (`STATE_UPDATE`, `PLAYER_ACTION`, plus a `DEAL_HAND` action accepted only from the current dealer), Host validation against forged messages, and host-drop terminates the game.
4. **UI:** landing (Create / Join only), 8-seat radial table via Grid, "Sit Here" seats, dealer button and blind markers, oversized cards, shrinking-ring timer, chip stacks with numeric overlay, showdown panel with "Deal next hand", and 320px responsive.
5. **Persistence and polish:** auto-fill name and emoji avatar, 12-char name cap, positive-integer buy-in, XSS-safe rendering (`textContent` only), a11y (contrast, four-colour deck, ARIA).
6. **Verification:** unit tests, two-browser manual test, 320px check, DoD checklist, GitHub Pages deploy.

## Guardrails
- Layout uses Flex/Grid only, with no pixel-offset centering.
- DOM code is separate from logic, and all listeners are named functions for cleanup.
- JSDoc on every function, a "Last Modified" header on each file, and no placeholders.
- A changelog entry accompanies each milestone.
